### 场景 1: 用户发送消息（缓存阶段）

```

   │
   ▼

   │
   ├─> AI 生成回复
   │
   ├─> 构建上下文
   │   ├─> 从数据库加载概要 (ChatRecordZip)
   │   └─> 从缓存加载历史 (Redis) 或 从数据库加载 (ChatRecord)

   └─> CacheChatService.cacheChatMessage()

       │   └─> Redis: spring_ai_alibaba_chat_memory:{conversationId}

       └─> RedisUtils.setExpireMarker()
           └─> Redis: chat:expire:{conversationId} (TTL: expireSeconds)
```

```

   ▼

       ├─> RedisUtils.removeAIRecordCache()
       └─> RedisUtils.removeExpireMarker()
```

## 关键设计决策

### 1. 为什么使用过期标记键？

**问题**: 直接给聊天记录键设置 TTL 会导致数据丢失

**解决方案**: 使用单独的过期标记键
- 聊天记录键: 不设置 TTL，持续累积消息
- 过期标记键: 设置 TTL，触发持久化事件
- 持久化完成后，同时清理两个键

### 2. 为什么使用异步处理？

**原因**:
- 持久化操作耗时（数据库写入 + AI 生成摘要）
- 避免阻塞 Redis 事件处理线程
- 提高系统响应性能

**实现**:
```java
@Async
public void onMessage(Message message, byte[] pattern) {
    // 异步执行持久化
}
```

### 3. 为什么需要批量插入？

**性能对比**:
- 单条插入: N 次数据库连接 + N 次 SQL 执行
- 批量插入: 1 次数据库连接 + 1 次 SQL 执行

**实现**:
```xml
<insert id="batchInsert">
    INSERT INTO chat_record (...) VALUES
    <foreach collection="list" item="record" separator=",">
        (...)
    </foreach>
</insert>
```

## 扩展性设计

### 1. 支持多种缓存实现

```java
public interface CacheChatService {
    // 接口定义，支持多种实现
}

// 实现 1: Redis
@Service
public class RedisCacheChatService implements CacheChatService { }

// 实现 2: 内存（已有）
@Service
public class DefaultCacheChatServiceImpl implements CacheChatService { }
```

### 2. 支持自定义过期策略

```java
// 可以根据对话类型设置不同的过期时间
public enum ConversationType {
    QUICK(1800),      // 快速咨询: 30分钟
    NORMAL(3600),     // 普通对话: 1小时
    DEEP(7200);       // 深度讨论: 2小时
    
    private final int expireSeconds;
}
```

### 3. 支持持久化失败重试

```java
@Retryable(
    value = {Exception.class},
    maxAttempts = 3,
    backoff = @Backoff(delay = 1000)
)
public void persistChatMessages(String conversationId) {
    // 持久化逻辑
}
```

## 性能指标

### 预期性能

| 操作 | 响应时间 | 说明 |
|------|---------|------|
| 缓存消息 | < 10ms | Redis 写入 |
| 读取缓存 | < 5ms | Redis 读取 |
| 自动持久化 | 100-500ms | 异步执行，不影响用户 |
| 批量插入 | 50-200ms | 取决于消息数量 |
| AI 生成摘要 | 1-3s | 取决于 AI 服务 |

### 资源使用

- **Redis 内存**: 每条消息约 1KB，1000 条对话约 1MB
- **数据库空间**: 每条记录约 500 bytes
- **线程池**: 建议配置 5-10 个异步线程

## 总结

### 架构优势
1. **解耦**: 缓存、持久化、摘要生成各自独立
2. **可靠**: 自动降级、错误处理完善
3. **高效**: 批量操作、异步处理
4. **灵活**: 支持自动和手动两种持久化方式

### 技术栈
- **缓存**: Redis (Jedis)
- **持久化**: MyBatis-Plus
- **异步**: Spring @Async
- **事件**: Redis Keyspace Notifications
- **AI**: Spring AI
